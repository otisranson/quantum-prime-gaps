# Scaling the landscape/portrait to 6 qubits — results (2026-08-11)

The landscape/portrait pipeline (re-upload encoding → QFT → amplitude readout)
defaulted to 4 qubits (16 basis states). This run switches its default to 6 qubits
(64 basis states) — the same register size the prediction pathway's amplitude
encoding was already fixed to — via `git commit 5b29ca2`. Command run:

```bash
./.venv/bin/python quantum_prime_gaps/quantum_prime_gaps.py
```

(no flags — 6 qubits is now the default; `--qubits 4` still works if the old
resolution is wanted for comparison.)

> **Note on the PNGs linked below:** same as [NOTES.md](./NOTES.md) — `output/*.png`
> is gitignored and regenerated by every run, so these links only resolve locally.

## What changed at 6 qubits vs. 4 qubits

| | 4 qubits (old default) | 6 qubits (new default) |
|---|---:|---:|
| Basis states (dim) | 16 | 64 |
| Re-upload chunks (49 gaps / qubits) | 13 | 9 |
| Circuit gate count | 102 | 104 |
| Real gap-sequence entropy | 3.3466 bits | 5.3872 bits |
| Mean shuffled-control entropy | 3.3948 bits | 5.4045 bits |
| Ordering looks structured (real < shuffled) | ✅ True | ✅ True |
| Primes among basis-state indices | 6 (of 16) | 18 (of 64) |

Entropy scales with dim as expected (more basis states → more bits to spread
probability across); the real-vs-shuffled gap (real slightly lower than shuffled,
i.e. "looks structured") holds at both resolutions, which is mild evidence this isn't
a resolution-dependent artifact — though it's still the soft check, reported not
asserted, same caveat as before.

All hard checks still pass at 6 qubits: primes match the independent sieve,
probabilities sum to 1, and the from-scratch numpy reference simulator still matches
Qiskit's statevector to floating-point precision (this comparison is now over a 64×64
matrix instead of 16×16 — still exact, just larger). Runtime for the full script
(landscape + portrait + prediction phase) is ~2.4s, no meaningful slowdown.

## What did *not* change

The prediction-phase numbers (backward verification, forward prediction, candidate
zones) are **identical** to the 4-qubit run in [NOTES.md](./NOTES.md), because
`fourier_extrapolate` / `backward_verify` / `spectral_candidate_zones` operate on the
raw gap arrays via plain `np.fft.fft`, not through the `--qubits`-controlled re-upload
circuit — and the amplitude-encoding pathway's register (`AMPLITUDE_QUBITS = 6`) was
already fixed at 6 regardless of `--qubits`. So this change only affects what the
landscape/portrait plots look like, not the prediction verdict:

- Backward verification MAE: still 3.900, still doesn't beat either naive baseline
  (mean-gap 3.277, repeat-last 3.600).
- Forward prediction (gaps 50–59) and candidate zones: unchanged from the 4-qubit run.

See [NOTES.md](./NOTES.md) for those tables in full rather than duplicating them here.

## Takeaway

Scaling the encoding resolution up is a change to how finely the landscape/portrait is
read out, not a change to the prediction mechanism or its (still negative) backward
verification result. If finer frequency resolution is meant to help prediction
specifically, that would require wiring `--qubits` (or a new flag) into the
amplitude-encoding pathway's `AMPLITUDE_QUBITS`, which is a separate change not made
here.
